### Visually-aligned Retrieval-Augmented Long Video Comprehension
![[../../../../pic/1776186722955_d.png]]
### 核心工作
将 RAG 技术运用到长视频理解（Long Video Comprehension）中。作者观察到，现有 LVLM 理解长视频时，常见做法要么是：
1. 直接扩长上下文 / 增加采样帧数：代价高，而且帧太多会带来冗余，未必真正提升理解能力；
2. GPT-based Agent：把视频先处理成文档再交给强闭源模型，多轮交互成本高、速度慢，而且容易丢失与视觉内容强相关的信息。
所以这篇文章提出 Video-RAG：
不是单纯喂更多帧，而是先从视频里用外部工具抽取一批与视觉对齐的辅助文本，比如：
- OCR 文本
- ASR 语音转写
- 目标检测结果
然后再通过 RAG，只检索出和当前问题最相关的那部分辅助文本，和原视频帧一起送进 LVLM，帮助模型回答问题。这样既减少上下文压力，又补充了视频帧本身不容易直接表达的信息。

### 方法
#### 1. Query Decouple：先把问题拆成“检索请求”
用户输入一个关于视频的问题后，系统不是直接回答，而是先让 LVLM 只看文本问题，把它拆成一个结构化的 JSON 检索请求。这个请求主要包含三类需求：
- ASR 请求：问题里是否需要语音/字幕信息
- DET 请求：问题里涉及哪些物体
- TYPE 请求：需要的是计数、位置，还是物体关系
例子：
如果问题是“Mike 准备去图书馆时，桌子上还有几本书”，那么系统会拆成：
- ASR: “Mike is ready to go to the library”
- DET: [“book”, “table”]
- TYPE: [“num”, “loc”]
也就是说，它先把原问题变成“我要去视频里找哪类证据”。这一阶段本质上是在把自然语言问题转换成后续 RAG 检索可执行的查询。
#### 2. Auxiliary Text Generation：从视频中预先抽取三类辅助文本
系统会并行地从视频生成三种数据库。
- OCR 数据库：对采样帧做文字识别，抽取画面里的字幕、招牌、标题等文本
- ASR 数据库：从视频音轨中转写出语音内容
- DET 数据库：对关键帧做目标检测，得到物体类别与位置，再进一步组织成自然语言描述
这里很关键的一点是：
作者不是把整段视频暴力转成一大堆文本直接塞给模型，而是先建库，再检索。因为长视频里抽出来的文本会非常多，里面有大量无关内容，如果全部输入，反而会超过上下文限制、增加推理干扰。
具体来说：
- OCR 用 EasyOCR
- ASR 用 Whisper
- OCR/ASR 的文本再用 Contriever 编码，存进 FAISS
- 检测部分用 CLIP 相似度先选关键帧，再用 APE 这种开放词汇检测器，按问题里提到的物体去检测
#### 3. Retrieval：只取和当前问题最相关的辅助文本。
对于 OCR / ASR：
- 把问题和解析出来的请求一起编码
- 去 OCR / ASR 向量库里做相似度检索
- 只保留相似度高于阈值的文本块
这样拿到的就不是“视频里所有字幕 / 所有语音”，而是和当前提问相关的那部分证据。
对于目标检测：
- 先根据问题里提到的实体，选出相关关键帧
- 对这些帧检测物体
- 再把检测结果加工成更适合 LVLM 理解的文本形式，而不是裸坐标
作者把检测结果转成三类更自然的辅助信息：
- Object Location：物体在哪里
- Object Counting：各类物体有多少个
- Relative Relationship：物体之间的相对位置关系
例如不是简单写 `book: [x,y,w,h]`，而是改写成类似：
- “Object 1 is a book located at …”
- “Object counting: book: 2”
- “Object 1 (book) is on the table”
这样做的意义是：让检测信息从“机器格式”变成“更像语言模型能消费的证据”。
#### 4. Integration and Generation：把辅助文本和视频帧一起送进 LVLM
最后，系统把：
- 原始采样视频帧
- 检索出来的 OCR 文本
- 检索出来的 ASR 文本
- 整理后的目标检测文本
- 用户原始问题
按时间顺序整理后，一起喂给 LVLM，生成最终答案。形式上就是：
$$
O = LVLM(F_v, \text{Concat}(A_m, Q))
$$
其中 $A_m$ 就是合并后的辅助文本。

可以简单理解成：
> 原本模型只能“看帧 + 猜”；
> 现在变成“看帧 + 读字幕/语音/检测证据 + 再回答”。

### 方法
##### 1. 长视频不是“多看几帧”就能解决
长视频的信息量太大，直接扩视觉 token 很贵，而且很多帧是重复的。作者认为，比起盲目增加帧数，更有效的是补充结构化、问题相关的文本证据。
##### 2. 辅助文本能缓解跨模态对齐难题
很多 LVLM 本质上还是“语言模型为主，视觉对齐为辅”。所以模型对文本证据往往更敏感。
Video-RAG 的思路是：把视频中有用的信息转换成文本，再用 RAG 选出最相关的那部分，帮助模型把“问题”和“关键视频证据”更好对齐。
##### 3. 它不是替代视频帧，而是补充视频帧
作者没有完全把视频变成文档再扔给 LLM，而是保留视频帧输入，因为纯文本化会丢失视觉细节。
所以它是一个“视频帧 + 检索辅助文本”的混合方案。

### 实验结论
作者在 Video-MME、MLVU、LongVideoBench 上做了实验，结论是：
- 对 7 个开源 LVLM，Video-RAG 平均能带来 2.8% 的 Video-MME 提升
- 只额外加入大约 2.0K 文本 token
- 接到 72B 开源模型上时，性能能超过一些闭源强模型，例如在 Video-MME 上 LLaVA-Video 72B + Video-RAG = 77.4%，高于 GPT-4o 的 77.2%
消融实验：
- OCR、ASR、DET 三种辅助文本都有效
- 先检索再输入 比 “把所有辅助文本全塞进去” 更好
- 阈值设置很重要，太低会引入冗余，太高会漏掉有用信息；论文最终选了 0.3 作为折中
### 一句话总结
Video-RAG 的本质是：
用 OCR / ASR / 检测器把长视频转成“与视觉对齐的外部文本证据”，
再用 RAG 按问题筛选这些证据，
最后把“关键帧 + 关键文本证据”一起送进 LVLM，提升长视频理解能力。
